# Мобильный канал для парсера (телефон / модем)

Документ описывает, как пустить трафик парсера Авито через мобильный интернет
(USB-тетеринг телефона или модем Huawei E3372h), не затрагивая остальной трафик неттопа.

Проверено на: Pixel 8 (Android, USB-тетеринг), Huawei E3372h-153 (HiLink, веб-интерфейс).

---

## 1. Требования к SIM-карте

Обязательно:

1. **Публичный IPv4, без CGNAT.**
   WAN-адрес не должен быть из `10.x.x.x`, `100.64–127.x.x`, `172.16–31.x.x`, `192.168.x.x`.
   Проверка: веб-интерфейс модема → «Информация об устройстве» → IP-адрес WAN.
2. Открытый интернет без фильтрации (никаких «детских»/«белых списков»).
3. Разрешено использование в модеме/роутере, раздача не запрещена.
4. APN `internet`, тип PDP IPv4.

Важно: у обычных абонентских SIM «большой четвёрки» часто CGNAT.
Публичный адрес дают на M2M/корпоративных тарифах или как платную услугу.

Блокировка Авито проверяется отдельно: даже с публичным IP адрес может быть
в чёрном списке (мобильные пулы Авито режет).

---

## 2. Схема работы

```
парсер (docker) → 172.17.0.1:8888 (tinyproxy)
                        │  Bind <IP телефона/модема>
                        ▼
        таблица маршрутов 300 → шлюз мобильного интерфейса
                        ▼
                 телефон / модем → сеть оператора
```

Ключевой принцип: маршрут выбирается **по адресу источника** (`ip rule from <IP>`),
поэтому через мобильный канал ходит только прокси, а остальной неттоп — как обычно.

## 3. Быстрый запуск

### 3.1. Android (USB-тетеринг)

1. Подключить телефон кабелем **с линиями данных** (зарядный кабель не подойдёт).
2. Разблокировать, подтвердить «Разрешить доступ к данным».
3. Настройки → Сеть и интернет → Точка доступа и модем → **USB-модем**.
4. На неттопе проверить, что появился интерфейс:

```bash
ip -brief addr | grep -E '^enx|^usb'
lsusb | grep -iE 'google|apple|samsung|xiaomi'
```

5. Поднять канал:

```bash
sudo phone-channel
```

Скрипт сам: найдёт интерфейс, пропишет маршрут в таблицу 300, добавит правило
по источнику, поставит TTL 65, переключит tinyproxy на этот адрес и проверит выход.

### 3.2. iPhone (проверить при первой попытке)

1. Установить пакеты (один раз):

```bash
sudo apt install -y usbmuxd libimobiledevice-utils ipheth-utils
sudo modprobe ipheth
```

2. Подключить кабель, разблокировать, нажать **«Доверять этому компьютеру»**.
3. Настройки → **Режим модема** → включить.
4. Проверить интерфейс:

```bash
ip -brief addr | grep -E '^enx|^usb'
```

5. Запустить `sudo phone-channel`.

Если интерфейс не появился: `idevicepair pair`, затем повторно включить режим модема.

### 3.3. Модем Huawei E3372h (HiLink)

```bash
sudo modem-channel
```

Скрипт: поднимает `192.168.8.100`, маршрут в таблицу 200, правило по источнику,
TTL 65, переключает tinyproxy на модем, проверяет интернет.

Сессию данных модем держит сам (веб-интерфейс `http://192.168.8.1`).
Если сессия не поднялась — зайти в интерфейс и нажать «Подключить».

## 4. Проверка работоспособности

```bash
# 1. Прокси выходит через мобильный канал
curl -s -x http://127.0.0.1:8888 https://api.ipify.org

# 2. Обычный трафик неттопа не изменился
curl -s --noproxy '*' https://api.ipify.org

# 3. Из контейнера парсера
sudo docker exec airflow-avito-project-avito-parser-service-1 \
  sh -c "curl -s -m 15 -x http://172.17.0.1:8888 https://api.ipify.org"

# 4. Реальный запрос парсера (тестовый скрипт из репозитория)
sudo docker cp /home/yury/avito_parser/scripts/parser_proxy_check.py \
  airflow-avito-project-avito-parser-service-1:/tmp/t.py
sudo docker exec -e PYTHONPATH=/app/src -e PROXY=172.17.0.1:8888 \
  airflow-avito-project-avito-parser-service-1 sh -c "cd /app && python /tmp/t.py"
```

Ожидаемый результат теста парсера: `HTTP: 200`, 40–50 объявлений,
`«Доступ ограничен»: False`.

## 5. Переключение парсера на мобильный канал

Файл: `airflow-avito-project/... config.toml` (в контейнере `/app/config/config.toml`).

```toml
proxy_string = "172.17.0.1:8888"   # было: iparchitect_...@188.143.169.28:30505
proxy_change_url = ""              # для нашего канала не используется
```

Порядок:

1. Сохранить текущие значения (`cp config.toml config.toml.bak`).
2. Заменить `proxy_string`, очистить `proxy_change_url`.
3. Перезапустить сервис парсера.
4. Проверить сбор лотов и логи.

Откат: вернуть строки из `config.toml.bak` и перезапустить сервис.

## 6. Диагностика проблем

| Симптом | Причина | Решение |
|---|---|---|
| `lsusb` не видит телефон | кабель без данных / не подтверждён доступ | другой кабель, разблокировать, «Разрешить доступ» |
| Телефон только заряжается | режим «Только зарядка» | выбрать «Передача файлов», включить USB-модем |
| Интерфейс есть, интернета нет | не включён теринг / нет маршрута | включить режим модема, `sudo phone-channel` |
| Прокси отдаёт IP прокси-сервера | tinyproxy слушает старый `Bind` | проверить `grep ^Bind /etc/tinyproxy/tinyproxy.conf`, перезапустить |
| Авито 429 / «Доступ ограничен» | IP в чёрном списке (CGNAT/мобильный пул) | сменить SIM/оператора, проверить публичный IP |
| `curl` игнорирует `--interface` | в окружении задан `http_proxy` | добавить `--noproxy '*'` (он отключает и `-x`!) |
| `tinyproxy: Could not open config file` | AppArmor разрешает только `/etc/tinyproxy/tinyproxy.conf` | править основной конфиг, не создавать новый файл |
| WAN IP `10.x` / `100.64+` | CGNAT у оператора | заказать публичный IP или сменить тариф |

---

## 7. Важные мелочи

- `curl --noproxy '*'` **отключает** и `-x` — для проверки прокси его использовать нельзя.
- Порядок правил: `ip rule` с меньшим priority применяется раньше.
  Наши правила: 890 (телефон), 900 (модем), затем main.
- TTL выставляется в 65, чтобы до оператора доходило 64 (как с телефона).
- DHCP телефона добавляет default-маршрут в main — скрипт его удаляет,
  чтобы весь неттоп не ушёл в мобильную сеть.
- Модем и телефон одновременно могут быть настроены: у каждого своя таблица
  (200 и 300) и своё правило по адресу источника.
